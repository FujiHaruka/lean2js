# 保証の鎖を閉じる

`docs/binding-shapes-plan.md` が断片を 33/35 形・公開関数 58/67 本まで広げたあとに残った穴を、
上から下まで全部塞ぐための計画。

## 文脈

いま証明が届いていない場所は 5 つある。

| 穴 | いま受け持っているもの |
| --- | --- |
| `call` / `fnRef` と、それを通る公開関数 9 本 | `Agree` の全件検査（24431 件） |
| `noMatchingAlternative` を写せない（`useful` が `partial`） | コンパイル時の網羅性検査そのもの |
| `outOfFuel` を写せない（主張が「十分な燃料で」の形） | `Agree` が出荷時の 10000 で足りることを確かめている |
| AST からファイルのテキストまで（`Js.Expr.render` は `partial`、`runtime` は手書きの JS 文字列） | Node 上の差分テスト |
| `.d.ts`（利用者が実際に呼ぶ境界） | 手で書いた型と入口検査が揃っているという信頼 |

上から 3 つは主張の但し書き、下から 2 つは TCB の厚み。前者は「何を言えているか」、後者は
「どこまで言えているか」を決めている。

## ゴール

このマイルストーンの終わりに立っている場所。

- 出荷する公開関数 **67 本すべて**について、どんな引数でも、`eval` が値を返すなら生成モジュールの
  同名関数が同じ値を返し、`eval` が落ちるなら同じコードで落ちる。**但し書きは 1 つも付かない**
- `Agree` の実行時検査は回帰テストとして残るが、主張の裏付けではなくなる
- 保証の鎖が「Lean のリファレンス意味論 → JS の模型 → 出荷するファイルのテキスト」まで繋がり、
  TCB は「パーサの仕様と Node」に縮む
- `.d.ts` が約束する型を満たす呼び出しは、入口の実行時検査で弾かれない

## 非目標

これまでの判断を引き継ぐもの（Promise / async、クロージャ、公開境界に関数を出すこと、`sortBy`、
Float）に加えて、このマイルストーンで新たに外すもの。

| 外すもの | 理由 |
| --- | --- |
| JS 全体の字句・構文 | パーサが受けるのは**この処理系が出力する部分集合**だけでよい。JS を読む道具を作るのではなく、書いたものを読み返して同じ木に戻ることを言う |
| TypeScript の型検査器のモデル化 | `.d.ts` の健全性は「型を満たす値の集合」として述べれば閉じる。代入互換性の規則そのものは要らない |
| Node / V8 の正しさ | 模型と本物の JS の差は差分テストが受け持つ。ここは動かさない |
| 意味論に新しい概念を足すこと | 言語は凍ったまま。分母は 1 つも増やさない |

## Approach

原則が四つあり、Step の順序と刻み方はこの四つから出る。

**帰納の軸を先に揃える。** `fragment_correct_in` と `fragment_traps_in` は `InFragment` の**導出**に
ついての帰納になっている。呼び出しの本体は呼び出し式の部分項ではないので、この形のままでは `call` の
場合に帰納法の仮定が出ない。`typeSound` と同じく**燃料についての帰納**にし、断片は場合分けとして
使う。`eval` はどの形でも部分式を 1 段少ない燃料で評価するので、燃料の仮定は部分式にも呼び出し先の
本体にも同じ強さで効く。**この付け替えは覆う範囲を 1 ミリも動かさないコミットとして先に済ませる。**

**プログラム全体の不変条件は成果物から取り出す。** `call` を覆う主張は「呼び出し先の本体も型検査を
通る」を要る。これはプログラム全体についての性質だが、利用者に渡させるものではない ——
`compileProgram` が成功したことから取り出せる（`ProgramTyped`）。利用者から見える主張に但し書きは
増やさない。

**地面を掘るのは主張を閉じたあと。** テキストと `.d.ts`（Step D / E）は、いま証明が立っている場所の
下と横に地面を足す作業で、主張の文面（Step A–C）とは独立に進む。ただし順序は主張を先にする ——
但し書きが残ったまま地面を広げると、README の保証の組み立てを 2 回書き直すことになる。

**保証を弱めて緑にしない。** 証明が重いときに命題を弱めない。`sorry` で塞がない。実行時検査が
落ちたときにベクタを減らさない。これはこのリポジトリの不変条件で、このマイルストーンでも変わらない。

## Step A. 呼び出しを断片に入れる — 完了

**動いた数字**: 断片 33/35 → **35/35 形**、陽性・陰性が届く公開関数 58/67 → **67/67 本**、manifest の
`Claim` 12 → 13 本。生成した JS は 1 バイトも動いていない。

**帰納の軸は燃料になった。** `fragment_correct_in` / `fragment_traps_in` は `InFragment` の導出に
ついての帰納だったが、呼び出しの本体は呼び出し式の部分項ではない。`eval` はどの形でも部分式を 1 段
少ない燃料で評価するので、燃料についての帰納にすると部分式にも呼び出し先の本体にも同じ強さで効く。

**宣言単位の主張と同時に立つ。** 呼び出しの場合が要るのは「呼ばれた宣言について、その燃料で生成関数が
同じ値を返す」で、それは宣言単位の主張そのもの。式の主張（`AgreesAt` / `TrapsAt`）と宣言の主張
（`DeclAgrees` / `DeclTraps`）を 1 つの帰納で同時に上げる（`Decl.levels`）。入れ子の `let` は 1 つに
つき燃料を 1 使うので、帰納は「その燃料以下のすべて」を運ぶ。

**前置プログラムとの差が消えた。** 宣言は**全体プログラムに対して**コンパイルされるようになり、
「呼び出しは自分より前の宣言にしか行けない」は `callsPrecede` の明示の検査になった。コンパイラの
2 つのパスを突き合わせる補題（`compileExpr_types_irrel` の一族、275 行）はまるごと不要になった。

**途中で見つかったコンパイラの穴を 2 つ塞いだ。** どちらも証明が通らないことで見つかった。

| 穴 | 直し方 |
| --- | --- |
| `@f` が同名の束縛に影を作られると、`eval` は宣言を読み、生成 JS は束縛を読む | 束縛と衝突する関数参照をコンパイルエラーにした（呼び出しは以前から同じ検査を持っていた） |
| `.tag` の射影は判別子と衝突するが、拒んでいたのは型宣言時の検査だけだった | 射影そのものを拒むようにした。`InFragment` から但し書きが消え、断片が構文そのものになった |

**環境の不変条件が 2 つ増えた。** どちらも呼び出しが環境から行き先を読むために要る ——
参照環境が束縛する名前は文脈にもあること（`EnvTyped.inScope`）と、生成環境が持つ予約されていない
名前は参照環境も持つこと（`JsEnvAgrees.fresh`）。**利用者から見える主張に但し書きは増えていない。**

**保証の境界**: 動いた。README の「保証の組み立て」と `docs/mvp-plan.md` の到達点は同じコミットで
直してある。

## Step B. 網羅性検査を証明する — 完了

**動いたもの**: `Mirrorable` から `noMatchingAlternative` が外れた。trap 方向が除くのは `outOfFuel`
だけになった。

**`useful` は全域になった。** 降りる深さの上限（`usefulBudget`）を引数に取り、1 段ごとに減らす。
測度で悩まずに済み、`partial` が外れる。**使い切ったときは「useful」と答える** —— 網羅性検査は
そこで「網羅でない」とコンパイルエラーになり、通してしまう側には倒れない。出荷プログラムは今の
上限で通る（ゲートで確認済み）。

**健全性は `Exhaustive.lean`。** 「useful でない行列は、その列の型が取りうるすべての値ベクタを覆う」。
中身は行列の分割を値の側から読み直す 2 本 —— `specialize` した行列で覆えるなら元の行列でも覆える、
`defaultRows` でも同じ —— と、「型が付いた値はシグネチャの見出しのどれかを持つ」。

**`specialize` が幅を見るようになった。** 構成子パターンの引数の本数がその見出しの本数と違う行は、
そのまま並べるのではなく落とす。型検査を通ったパターンでは起こらないので受理する集合は変わらず、
落とす方向は「useful」に倒れるので安全側。

**保証の境界**: 動いた。README の「保証の組み立て」と `docs/mvp-plan.md` の到達点は同じコミットで
直してある。

## Step C. 燃料の但し書きを消す — D / E の後ろに回す

**目標**: `Mirrorable` から `outOfFuel` を外し、主張から「十分な燃料で」を落とす。

**順序を変えた理由**: 必要な燃料は**実行時のデータで決まる**。`map` は要素数だけ本体を評価するので、
式と宣言だけを見て上限を書く関数は作れず、`outOfFuel` を外すには本物の停止性（強正規化）の証明が要る。
残る 4 つの中でいちばん重く、しかも product として得るものはいちばん小さい —— 出荷するベクタについては
`Agree` が 10000 で足りることを毎回確かめていて、穴が残るのは出荷していない入力についてだけ。
先に D（テキスト）と E（`.d.ts`）で TCB を削る。

呼び出しは宣言順に前へしか進まず、走査はリストの構造に沿って進む。だから評価は必ず止まり、必要な
燃料はプログラムと引数から決まる。

- **C-1 燃料の単調性。** 値を返す評価は、燃料を増やしても同じ値を返す
- **C-2 コスト関数。** `cost : Program → Env → Expr → Nat` を定義し、`fuel ≥ cost → evalExpr ≠
  .error .outOfFuel` を示す。呼び出しの分は宣言の位置についての整礎再帰、走査の分はリストの長さ
- **C-3 主張から燃料を落とす。** `Mirrorable` から `outOfFuel` が外れ、`decl_traps` の但し書きが消える。
  `callFunctionAt` 側の「十分な燃料で」は生成コードの模型の話なので残るが、**リファレンス側の
  燃料切れは主張の穴ではなくなる**
- **C-4 出荷時の 10000。** 必要量を `emit` が計算して検査する形にし、README の最後の段落を落とす

## Step D. 生成テキストまで届かせる

**目標**: TCB を「レンダラと手書き JS」から「パーサの仕様と Node」へ縮める。

いま証明は `Js.Module` の AST で止まっていて、出荷しているのはそれを `render` したテキスト。間に
証明が無い。

- **D-1 レンダラを全域に — 完了。** `Js.Expr.render` / `TyDesc.render` / `tsType` は
  リストごとの相互再帰に書き直してあり、`partial` は付いていない。出力は 1 バイトも動いていない
- **D-2 字句 — 完了。** 数値とエスケープは `toString` と `String.foldl` を捨て、`LeanTs/Text.lean` の
  `List Char` 再帰にした。どちらも proof が展開できない壁で、読み返す側の証明が書けない。出力は
  1 バイトも動いていない。読む側は `LeanTs/Parse.lean` の `parseInt` / `parseStr` / `parseIdent` で、
  それぞれ「書いたものの後ろに何が続いていても、書いたものと残りを返す」形の往復補題を持つ
- **D-3 型記述子 — 完了。** `parseDesc (render d ++ rest) = some (d, rest)`。ついでに
  `TyDesc.ctors` が持っていた型名を落とした —— `render` は書かず `checkTy` は読まないのに、
  `render` を単射でなくしていた
- **D-4 読む側 — 完了。** 式・文・関数・モジュールを読む `Parse.lean`。出荷する `index.js` が
  コンパイラの作った AST に読み戻せることを **`emit` が書き出す前に検査する** ——
  `checkAgreement` と同じ位置で、出荷するテキストそのもので毎回確かめる

  **印字器は出荷ファイルそのものを書くようになった。** `Js.Module.render` は誰も呼んでおらず、
  出荷していたのは `emitModule` が組み立てる別のテキストだった。往復を言う相手が出荷ファイルで
  ないと主張が空になるので、`render` を出荷ファイル（末尾の `//# sourceMappingURL` まで）に
  合わせ、`emitModule` がそれを使うようにした。出力は 1 バイトも動いていない

  パーサの再帰は燃料で回す。上限は入力テキストの長さから取るので、**主張に燃料の但し書きは
  出ない**（Step C が消そうとしている意味論の燃料とは別物）
- **D-5 往復の証明 — 完了。** `LeanTs/Roundtrip.lean` の `parseModule_render` ——
  `RenderableModule m` なら `parseModule (Js.Module.render m).toList = some m`。

  **`Renderable` が除くのは、`render` が同じテキストに写す 3 か所と、自分を閉じる doc。**

  | 重なるテキスト | 除き方 |
  | --- | --- |
  | `.call "__ck" [e, d]` は `.check d e` と同じ。`__map` ほか 6 つの構成子も同じ | 呼び先と `.ident` の名前が、読み手が構成子に振り分ける 10 語（`true` / `false` / `new` と `__ck` ほか 7 つ）でないこと。`__i53` のような**構成子を持たないヘルパ名は素通り**する |
  | `.ident "true"` は `.bool true` と、`.ident "new"` は `dictLit` の頭と同じ | 同上 |
  | `.unary op` の `op` が任意の文字列 | `op` が `!` か `-` であること |

  加えて `Func.doc` は `/** */` の中に素で入るので、`" */\n"` を含まないことが要る
  （`noCommentClose`）。名前はすべて識別子であること。

  **燃料の仮定はテキストの長さ**（`(render e).toList.length < f`）。最上位はテキスト自身の長さを
  渡すので、主張に燃料の但し書きは残らない。型記述子の読み手だけは測度を取るので、
  `descSize d ≤ (render d).length` の橋を 1 本渡している。

  **証明の要は、`(` の後の先読み `( 識別子並び ) => (` が arrowCall 以外の括弧形では必ず失敗する**
  こと（`parseArrowHead_render`）。識別子並びは名前に使えない最初の文字で止まり、その文字は
  どの `render` でも `)` にならない —— `member` は `).` で閉じ、`binary` と `cond` は空白が来る。
  ここは部分式への帰納ではなく、構成子ごとの場合分けだけで閉じる。

  **印字器から `String.intercalate` が消えた。** 累算器を回すので proof が展開できない。
  引数名の並びは `Js.renderNames`、文の並びは `Js.Stmt.renderAll` という素の再帰にした。
  前置きと末尾の source-map 行も `Js.preamble` / `Js.sourceMapLink` という名前を持つ ——
  `runtime` の 4000 字を展開させないため。出力は 1 バイトも動いていない
- **D-5b `Renderable` を成果物から取り出す — 完了。** `LeanTs/Renderable.lean` の
  `renderableModule_of_compileProgram` —— `compileProgram p = .ok m → RenderableModule m`。
  **往復の主張から但し書きが消えた**: `parseModule_render_of_compileProgram` は
  「コンパイルが通ったなら、書き出したテキストは同じモジュールに読み戻る」を無条件で言う。
  `Axioms.lean` がこの行を固定している。

  **証明はコンパイラ自身の再帰**（`compileExpr.mutual_induct` の 56 場合）。生成木に入る名前は
  2 か所からしか来ない —— スコープと宣言で、どちらも `validateIdent` を通っている。演算子と呼び先は
  コンパイラが自分で綴る一握りで、読み手が構成子に振り分ける 10 語のどれでもない。`__p0` や `__i53`
  のような予約接頭辞のヘルパ名は、構成子を持たないので素通りする。

  **`Ty.render` は全域になった。** doc コメントは型の描画から組み立てられるので、`partial` のままでは
  その文字について何も言えない。`Js.Expr.render` と同じ書き換え —— リストごとの相互再帰 —— で、
  出力は 1 バイトも動いていない。`String.intercalate` も印字器と同じ理由で落とし、パラメータの並びは
  `declSig` という素の再帰にした。**doc が `*/` を閉じないことは「`*` を 1 文字も含まない」から出る**
  —— 型名もフィールド名も識別子で、間に入るのは括弧・コロン・矢印だけ。

  `emit` の実行時検査は回帰テストとして残る
- **D-6 `runtime` を AST にする。** 手書きの 200 行あまりの JS 文字列を `Js` の AST として持ち直し、
  `JsSem.helper` が仮定している等式をその AST の意味論から出す。ここが TCB のいちばん厚い層
- **D-7 往復を出荷する — 完了。** manifest の `Claim` が 14 本になった —— 14 本目の
  `file_reads_back` は「この例題のために書き出した `index.js` は、コンパイラが作ったモジュールに
  読み戻る」。README の保証の組み立てに「テキスト」の行が入り、AST と出荷ファイルの間が証明で埋まった。
  残る TCB は**パーサの仕様**（読み戻せることが「同じテキストである」を意味すること）**と Node**、
  そして `runtime` の手書き JS（D-6）

## Step E. `.d.ts` の健全性

**目標**: TS で型が通る呼び出しは、入口の実行時検査で弾かれない。

`.d.ts` は利用者が実際に読む唯一の型だが、そこだけ手で書いた対応の信頼で繋がっている。

- **E-1 TS 型を値の集合として定義する。** `tsType` が出す構文に対して「その型を満たす JsValue」を
  帰納的に定める。判別可能なユニオンと型パラメータがそのまま中身になる
- **E-2 入口検査との一致。** `tsType ty` を満たす値は `checkTy` を通り、通る値は `tsType ty` を満たす。
  `Int53` と `UInt32` は JS では区別が無いので、この 2 つの取り違えだけは境界の外に残る（入口検査が
  すでにそう言っている）
- **E-3** README の保証の組み立てに `.d.ts` の行を足す

## 順序と依存

```
A（呼び出しを断片に入れる・完了）   断片が構文そのものになった
  ↓
B（網羅性・完了）                  Mirrorable に残るのは outOfFuel だけになった
  ↓
D（テキスト）→ E（.d.ts）          TCB を削る。D-1〜D-5（印字器・字句・型記述子・読む側・往復）は完了
  ↓
C（燃料）                          いちばん重く、得るものはいちばん小さいので最後
```

**B は A より後**（断片が閉じていないと `Mirrorable` を外しても届く範囲が変わらない）。D と E は
どれとも独立で、C を待たずに進む。

## 守ること

- **保証を弱めて緑にしない。** 実行時検査が落ちたときに、検査対象のベクタを減らさない
- **`sorry` で塞がない**（塞げば `Axioms.lean` が落ちる）
- **manifest に定理を足したら `Axioms.lean` に行を足す**
- **帰納の軸を付け替えるコミットは、覆う範囲を動かさない。** 同じ主張が同じ形で通ることを見る
- **数字を動かしたら引用元を同じコミットで直す。** 断片が覆う形の数・関数の本数・ベクタ件数は
  `README.md` と `docs/mvp-plan.md` が引用している
- **保証の境界を動かしたら**、README の「保証の組み立て」と `docs/mvp-plan.md` の到達点を同じコミットで
  直す
- **プッシュ前にゲートを全部ローカルで通す。** 一部だけ回した結果を判断に使わない
